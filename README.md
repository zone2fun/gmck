# GMCK

Mobile-first PWA foundation for an 18+ gay and bisexual men's community in Thailand.

## Stack

- Next.js 16 App Router + TypeScript
- Tailwind CSS 4
- Supabase Auth / PostgreSQL / Realtime (project: gmck, Tokyo)
- PWA manifest foundation

## Local development

1. Install Node.js 22 or newer.
2. Install dependencies: `npm install`
3. Copy `.env.example` to `.env.local`.
4. Add the Supabase Project URL and publishable key from the Supabase Dashboard.
5. Start: `npm run dev`

## Security notes

- Never commit `.env.local`, Supabase secret keys, or service-role keys.
- The browser may only receive the Supabase publishable key.
- Do not add real member data until database RLS policies and authorization tests are reviewed.
- Age assurance, location privacy, moderation, reporting, and rate limits are required before public launch.

## Current milestone

Phase 0: app shell, responsive dark theme, PWA manifest, and Supabase client factories.
Authentication and database features are intentionally not enabled yet.


## Native mobile apps (Android + iOS)

GMCK is being prepared as a Capacitor 8 native shell around the existing Next.js application. The production web app and Supabase backend remain the source of truth; the shell currently loads `https://gmck.vercel.app`. This avoids incorrectly trying to static-export Next.js routes that depend on server rendering and Supabase SSR.

### Requirements

- Node.js 22+
- Android: Android Studio with Android SDK
- iOS: macOS with Xcode 26+ and CocoaPods
- Apple Developer Program membership for App Store distribution
- Google Play Console developer account for Play Store distribution

### Create native projects (run from the repository root)

```bash
npm install
npx cap add android
npx cap add ios
npx cap sync
```

Open native projects:

```bash
npx cap open android
npx cap open ios
```

Android builds are produced from Android Studio. iOS archives are produced in Xcode on macOS. Commit the generated `android/` and `ios/` directories after creating and configuring them so the native projects are versioned.

### Important release work still required

- Confirm the final unique application ID / Apple Bundle ID before the first store submission. Current provisional ID: `com.gmck.app`.
- Configure Google OAuth and Supabase redirect URLs for installed apps and verify the complete sign-in / sign-out flow on real devices.
- Configure native push delivery (FCM for Android and APNs for iOS), register device tokens securely, and connect the server-side sender. The existing Web Push subscription flow is not a replacement for APNs/FCM.
- Add and verify Android App Links / iOS Universal Links and the domain association files.
- Add native permission descriptions for camera, photo library, and location only where those features are used.
- Prepare store screenshots, privacy policy URL, support URL, account deletion flow, age rating, and data-safety / App Privacy disclosures.
- Complete user-generated-content safeguards: reporting, blocking, moderation response process, and published contact information.
- Test purchases/subscriptions (if enabled) against Apple and Google billing rules.
- Test on physical Android and iPhone devices, including poor connectivity, OAuth return, push permission, camera upload, location permission, and account deletion.

### Current implementation boundary

The Capacitor configuration and dependencies are in place, but native platform projects, signing credentials, push-provider credentials, store listings, and release binaries are not generated by GitHub source edits. The remote web shell requires an internet connection and is a development/release-preparation stage, not an offline-capable native rewrite. App Store and Play Store approval cannot be guaranteed; Apple may require additional native functionality beyond a thin web wrapper.
